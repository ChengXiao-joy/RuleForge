# 变更记录（CHANGELOG）

本项目采用「分阶段交付」方式开发，每个阶段独立验收后进入下一阶段。以下按时间线记录 V1.0 的完整迭代链路。

## V1.0 —— 完整原型（6 个阶段全部交付）

### 阶段0：需求底座
- **开发内容**：PRD（用户故事 / MVP·二期划分 / 异常场景 / 风险清单）；冻结 Rule Schema（条件树、动作、优先级、生效范围、版本、冲突结构体）；Git 仓库与五层目录初始化；Claude API 接入 + SQLite + 日志模块；自然语言→规则树 Prompt + JSON 校验 + 最多 2 次重试；测试用例库。
- **能力**：自然语言翻译为结构化规则树；缺陷输入返回「需要澄清」；本地一键启动。
- **修复/关键问题**：Windows GBK 控制台中文乱码与 emoji 崩溃 → 强制 UTF-8 输出；`model_copy` 不触发校验导致测试误判。

### 阶段1：规则基础管理与单规则自检
- **开发内容**：规则 CRUD（新增/查询/修改/删除 + 版本递增）；Streamlit 前端（新增/列表/详情/编辑/删除）；单规则自检器（条件为空/字段非法/表达式语法错误/单条内部死条件）；保存时自动触发自检。
- **能力**：增删改查落库、刷新不丢失；缺陷规则识别并明确告警。
- **修复/关键问题**：详情页删除缺失二次确认；`StreamlitWidgetAlreadyInstantiatedError`（nav 键后写）→ pending_nav 约定；时间显示改用北京时间并统一 `yyyy-mm-dd hh:mm:ss` 格式。

### 阶段2：多规则冲突检测
- **开发内容**：冲突检测引擎（互斥/覆盖/冗余三类，纯自研 DNF 条件归一化 + 区间/集合蕴含判定）；批量冲突扫描入口；冲突记录落库；冲突报告页；LLM 通俗解释（仅翻译，不参与判定）。
- **能力**：识别三类冲突；坏规则自动过滤并在报告标注；冲突结果快照式持久化。
- **修复/关键问题**：值冻结 list→tuple 导致 between/in 蕴含漏判；「notify vs block 不算相反」的判定语义修正；删除规则时同步清除涉及它的冲突记录。

### 阶段3：规则版本管理、快照、Diff
- **开发内容**：版本快照（新增/编辑自动快照、手动打标签、删除归档软删除）；规则 Diff 工具（新增/删除/值变更，点分路径定位）；版本历史页；LLM 变更说明。
- **能力**：任选两版本结构化对比；删除规则版本数据软删除归档保留。
- **修复/关键问题**：`insert_snapshot` 未写 tag 导致导入重建时标签丢失。

### 阶段4：沙箱仿真推演 + 影响范围分析
- **开发内容**：沙箱推演引擎（纯函数隔离、13 种操作符求值、按优先级命中、完整链路记录）；影响分析（覆盖下游/冲突/依赖识别）；沙箱仿真页 + 详情页影响分析面板；推演记录独立持久化。
- **能力**：样本推演不改正式数据；识别规则间冲突/覆盖/依赖关联。
- **修复/关键问题**：影响分析误把「其它规则之间的冲突」计入目标规则 → 过滤为只保留涉及目标的关联。

### 阶段5：批量导入导出、数据看板、项目收尾
- **开发内容**：JSON 批量导入导出（含版本快照、导入预览、覆盖导入双重确认、坏数据拦截+报告）；数据看板（六指标卡 + 状态分布图 + 近7天版本图）；全站交互/异常兜底/帮助弹窗/编辑草稿缓存；requirements 锁定版本、README、LICENSE、一键启动脚本、自动化自测脚本。
- **能力**：双向兼容导入导出；看板统计实时准确；自测脚本 8/8 核心链路。
- **修复/关键问题**：空样本推演产生误导性 0 命中 → 拦截空输入；`sandbox_sample` 组件键后写 → on_click 回调；`.env_beifen` 备份未纳入 gitignore → 补 `.env_*` 忽略规则。

---

## 迭代链路小结

```
阶段0 底座 → 阶段1 单规则 → 阶段2 多规则冲突 → 阶段3 版本/Diff → 阶段4 沙箱/影响 → 阶段5 收尾打包
```

每个阶段的确定性能力（自检、冲突、推演、Diff、导入校验、统计）全部**自研代码实现**，LLM 只承担「自然语言→规则树」「结果→中文解释」两件事，贯穿始终，避免幻觉。
