# 演示样例包说明

本目录提供 3 套可直接导入的规则 JSON 样例，用于快速演示 RuleForge 的核心能力。
导入入口：网页「批量导入导出」页 → 粘贴 JSON 或上传文件 → 「🔍 预览导入」→「✅ 确认导入」。

> 样例中的规则 ID 均为独立前缀（OFF- / MUT- / SIM-），互不冲突，可重复导入到同一库。

| 样例文件 | 演示目标 | 导入后怎么验证 |
| --- | --- | --- |
| `office_rules.json` | **单规则自检 + 规则管理**（3 条彼此独立的合法规则） | 到「规则详情/编辑」查看规则树与「✅ 自检通过」；可编辑制造坏规则看告警 |
| `conflict_rules.json` | **多规则冲突检测**（4 条规则，形成 2 组互斥） | 到「规则列表」点「🔍 批量冲突扫描」→ 冲突报告出现 **2 条 🔴 互斥冲突**（8折审批↔订单拦截、大额特批↔风控拦截） |
| `sandbox_rules.json` | **沙箱仿真推演**（4 条规则带优先级梯度） | 到「沙箱仿真」输入样本 `order.amount=8000` + `customer.level=VIP` → 命中 3 条，按优先级「高额订单拦截(70) → VIP大额订单特惠(60) → VIP普通折扣(50)」，最终结论 = 拦截 |

## 样例设计要点（便于讲解）

- **office_rules.json**：字段名用英文 snake_case（如 `attendance.monthly_late_count`），操作符/动作类型全部落在冻结的 Schema 枚举内，导入时单规则自检全部通过——演示「合法规则干净入库」。
- **conflict_rules.json**：每组用「相同触发条件 + 相反动作」（`approve` vs `block`），命中阶段2 冲突引擎的「互斥冲突」判定（`mutual_exclusion`）——演示「LLM 不参与、纯自研代码判定」。
- **sandbox_rules.json**：刻意拉开优先级（70/60/50），并混入一个「与推演样本无关」的人事规则——演示沙箱「按优先级命中 + 最终结论 + 未命中规则」的完整链路。
