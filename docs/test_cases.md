# 测试用例库（阶段0）

> 数据源：`tests/test_cases.json`（机器可读）
> 覆盖场景：人事、销售、个人生活；覆盖类型：正常规则、缺陷规则、冲突样例

---

## 1. 验收样例（10 条，用于解析验收评测）

验收标准：**10 条样例 ≥8 条一次输出合法 JSON**，格式错误自动重试（≤2 次）。
运行：`python tests/run_parser_eval.py`（需配置 `ANTHROPIC_API_KEY`）。

「合法 JSON」判定：LLM 首次输出能被解析为符合 `LLMResult` 信封（`rule` 或 `clarification` 均可）。

### 1.1 正常规则（6 条）

| ID | 场景 | 输入 | 期望结果 |
| --- | --- | --- | --- |
| T01 | 人事 | 如果员工本月迟到超过3次，就发邮件提醒人事部门 | rule（notify） |
| T02 | 人事 | 如果员工连续缺勤超过5天，就自动发起离职面谈审批 | rule（approve） |
| T03 | 销售 | 如果订单金额超过1000元且客户是VIP，就批准打8折 | rule（and 逻辑节点） |
| T04 | 销售 | 如果客户过去半年消费金额超过5000元，就给客户打上高价值标签 | rule（tag） |
| T05 | 个人生活 | 如果今天气温低于10度，就提醒我穿厚外套 | rule（personal） |
| T06 | 个人生活 | 如果信用卡账单金额超过5000元，就提醒我尽快还款 | rule |

### 1.2 缺陷规则（4 条）

| ID | 输入 | 缺陷类型 | 期望结果 |
| --- | --- | --- | --- |
| T07 | 处理一下 | 输入过于笼统 | clarification |
| T08 | 发邮件提醒人事部门 | 只有动作、缺触发条件 | clarification |
| T09 | 如果员工本月迟到超过3次 | 只有条件、缺执行动作 | clarification |
| T10 | 今天天气怎么样 | 根本不是一条规则 | clarification |

## 2. 冲突样例（2 条，供阶段1 冲突检测引擎使用）

> 结构上均为「正常规则」（可正常解析），但两两组合构成冲突。阶段0 只冻结结构、不做检测。

| ID | 场景 | 输入 | 与谁冲突 |
| --- | --- | --- | --- |
| C01 | 销售 | 如果客户是VIP，就批准打8折 | 与 C02 动作冲突 |
| C02 | 销售 | 如果客户是VIP，就批准打9折 | 与 C01 动作冲突 |

**冲突说明**：C01 与 C02 触发条件相同（`customer.level == "VIP"`），但动作对同一字段 `discount` 给出不同取值（0.8 vs 0.9），属于 `action_conflict`（动作冲突）。阶段1 冲突检测引擎应输出 `Conflict` 结构体标记此冲突。
