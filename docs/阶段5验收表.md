## 一、验收标准1：JSON 导入导出（双向兼容 / 精准报错 / 预览流程）

| # | 检查项 | 操作 | 预期结果 | 通过 |
| --- | --- | --- | --- | --- |
| 1.1 | 导出全部规则 | 网页「批量导入导出」→ 勾选「导出全部」→ 生成导出 JSON → 下载 | 文件含全部规则，每条带 `rule` 完整数据 + `versions` 版本快照（版本号/备注/标签/时间/该版本完整JSON） | ☐ |
| 1.2 | 导出选中规则 | 取消「导出全部」→ 多选若干条 → 生成 | 只含选中的规则 | ☐ |
| 1.3 | CLI 导出 | 双击「shortcuts」→「导出.bat」 | 提示「已导出到 rules.json（共 N 条规则）」 | ☐ |
| 1.4 | 导入预览不落库 | 粘贴任意 JSON → 点「🔍 预览导入」 | 出现预览面板：总数 + ✅可导入/⚠️已存在/❌校验失败 分类计数 + 逐条表格（序号/规则名/ID/状态/原因）；**此时规则列表数据无任何变化** | ☐ |
| 1.5 | 全新规则确认导入 | 预览后点「✅ 确认导入」 | 「全部导入成功：N 条」，规则列表出现新规则 | ☐ |
| 1.6 | 异常条目精准报错 | 粘贴「1条好规则+1条中文字段坏规则+1条缺字段规则」混合 JSON → 预览 → 确认导入 | 报告精确到条目：**序号+规则名+失败原因**（自检失败/Schema 不合）；好规则照常导入，**不被坏条目阻断** | ☐ |
| 1.7 | 重复 ID 默认拦截 | 导入一份与库内同 ID 的 JSON（不勾覆盖） | 该条报「规则 ID 已存在，跳过导入」，库内原规则未被改动 | ☐ |
| 1.8 | 覆盖导入双重确认 | 勾选「☑️ 覆盖已存在的规则」→ 此时「✅ 确认导入」按钮**禁用** → 再勾选「我确认要覆盖库内同 ID 规则」→ 按钮可用 → 导入 | 未确认时无法导入；确认后同 ID 规则被替换（名称/条件变为导入内容），其版本快照被重建 | ☐ |
| 1.9 | 双向兼容（往返一致） | 导出 A 库 → 导入到全新临时库 → 对比 | 规则数据、版本号、快照条数、备注、标签完全一致 | ☐ |
