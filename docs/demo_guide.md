# 面试演示指引（demo_guide）

一条标准演示流程，约 10~15 分钟。按顺序操作，每步标注「面试官重点」亮点。

## 0. 启动项目

双击项目根目录 `run.bat`（或 `shortcuts\启动网页.bat`），浏览器自动打开 `http://localhost:8501`。

> 面试官重点：一键启动 = 自动建环境→装依赖→查配置→起服务，体现「可交付、可复现」。

## 1. 自然语言新建规则（阶段0/1）

1. 进入「新增规则」，输入：`如果员工本月迟到超过3次，就发邮件提醒人事部门`
2. 点「解析并自检」→ 看到结构化规则树 + 「✅ 自检通过」→ 保存

> 面试官重点：**LLM 只做翻译**（自然语言→规则树），翻译结果立刻被自研代码校验；再输入「处理一下」会得到「需要澄清」而不是硬凑，体现 LLM 边界设计。

## 2. 制造一条坏规则看自检告警（阶段1）

输入：`如果订单金额超过1000元且订单金额低于500元，就批准打折` → 解析并自检

> 面试官重点：红色告警「约束区间无交集，条件不可能成立」——这是**自研确定性自检**，不是 LLM 判断。

## 3. 导入冲突样例看冲突检测（阶段2）

1. 「批量导入导出」→ 粘贴 `docs/samples/conflict_rules.json` 内容 → 预览导入 → 确认导入
2. 「规则列表」→ 点「🔍 批量冲突扫描」→ 冲突报告出现 **2 条 🔴 互斥冲突**
3. 展开一条点「🤖 生成通俗解释」

> 面试官重点：冲突判定是**纯自研算法**（条件树 DNF 归一化 + 蕴含判定）；LLM 只是把判定结果翻译成中文，**不参与判断**——这是本项目最核心的架构亮点。

## 4. 编辑规则生成版本快照 + Diff（阶段3）

1. 进入某条规则 → 编辑（填修改备注）→ 保存，再改一次保存（版本号递增）
2. 「版本历史」→ 打标签「上线版」→ 选两个版本「对比」→ 看差异高亮 → 「🤖 AI 生成变更说明」

> 面试官重点：每次保存自动留「修改前/后」快照，Diff 是**自研结构化比对**（新增/删除/值变更按字段路径定位），不是用 LLM 对比。

## 5. 导入沙箱样例做推演（阶段4）

1. 「批量导入导出」→ 导入 `docs/samples/sandbox_rules.json`
2. 「沙箱仿真」→ 点「✨ 填入示例样本」再改金额为 `8000`，点「🚀 一键推演」

> 面试官重点：推演**纯内存计算、零写库**（隔离性），按优先级输出命中链路和最终结论；演示完回看规则列表数据无变化。

## 6. 数据看板收尾（阶段5）

回到「📊 看板首页」→ 六项统计卡 + 状态分布图 + 近7天版本图。

> 面试官重点：统计与库内数据实时一致、只读；整个项目五层架构（llm_layer / rule_engine / ui / storage / utils）职责清晰。

## 一句话总结（面试收尾）

> 「RuleForge 把 LLM 严格限定在『翻译』这个不可替代的环节，而把冲突检测、自检、推演、Diff 这些需要**确定性**的环节全部自研，从架构上避免了幻觉——这正是 LLM 应用里最值得讲清的工程边界。」
